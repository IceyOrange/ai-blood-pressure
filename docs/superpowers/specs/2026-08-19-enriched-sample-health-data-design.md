# 丰富健康样例数据设计

## 目标

- 保留 `data/sample-data.js` 的现有字段和页面行为。
- 补充未来可获取的测量质量、测量背景、用药、症状、活动、体重、临床档案和检验数据。
- 保持时间、来源和医学含义一致，供后续个性化分析使用。

## 非目标

- 本次不修改 `agent.js`、`api/chat.js`、页面组件或 Gemini 提示词。
- 本次不让新增字段进入 Agent 上下文，也不接入真实设备或数据库。
- 样例数据不编码诊断、处方或自动调药结论。

## 数据结构

采用向后兼容的分层结构，保留原字段并增加以下内容：

- `profile`：绝经、吸烟、家族史、确诊信息、医生目标和过敏史。
- `clinicalProfile`：重要病史、风险因素、门诊与随访计划及来源。
- `device`：认证、袖带规格、自检、固件、来源和测量侧别支持。
- `measurements[]`：测量侧、姿势、静坐时间、袖带、连续测量组、原始读数、餐后/服药/咖啡/运动等时间关系、压力、疼痛、质量标记和症状引用。
- `medications` 与 `medicationEvents`：处方计划及实际服药事件。
- `symptomEvents`：症状起止、严重程度、关联测量、危险信号和处理结果。
- `diet[]`：估算来源、咖啡因、酒精标准杯、饮水、餐次和完整度。
- `sleep[]`：主观质量、打鼾、夜间心率、平均与最低血氧及来源。
- `activity`：步数、中高强度活动、久坐和运动时间。
- `weightHistory`：体重、腰围、测量时间和来源。
- `labResults`：肾功能、血钾、血糖、糖化血红蛋白和血脂，包含单位、参考范围、采样时间、来源和异常标记。
- `goals`：医生家庭血压目标、活动与体重目标、连续测量要求、来源和更新时间。

## 一致性规则

- 保留现有 27 条血压、14 条饮食和 14 条睡眠记录，不改变当前图表和血压统计。
- 最新血压保持 `128/82 mmHg`、心率 `72 次/分`。
- 高盐、晚餐偏晚、睡眠较差或压力较高可与相对较高血压同时出现，但不写成确定因果。
- 用药事件与测量时间保持合理先后关系，不用漏服制造危险读数。
- 症状与测量通过 ID 关联，样例只包含轻微、非急症症状。
- 推测与本人反馈分别标记来源和置信度；缺失值使用 `null`、空数组或完整度字段。

## 验证

- 验证样例文件仍可作为 JavaScript 模块解析。
- 验证原记录数量、最新读数和近 7 天血压统计不变。
- 验证新增顶层集合、关键字段、引用 ID、时间戳、单位和来源。

## 后续个性化分析

分析优先使用硬件测量与质量标记，其次使用医生目标和已确认病史，再结合用药、症状和同时间窗口的生活方式记录。流程先排除测量质量与急症风险，再描述趋势和时间关联，最后给出少量可执行且不涉及自行调药的建议。
