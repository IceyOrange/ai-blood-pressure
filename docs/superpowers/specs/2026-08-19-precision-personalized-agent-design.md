# 精准个性化健康 Agent 设计

## 目标

- 让用户在很短的回答中明确感受到 Agent 理解其医生目标、测量条件、用药、症状和生活节奏。
- 让所有个性化数字与事实来自确定性工具，Gemini 只负责选择重点和精炼解释。
- 控制信息密度：结论 2 至 3 句，个性化证据最多 3 条，行动建议最多 2 条。
- 保留急症优先、禁止自行调药、相关性不等于因果等安全边界。

## 数据流

1. `buildDoctorBrief` 在现有摘要外增加 `personalization`，携带临床档案、测量质量、用药事件、症状、饮食、睡眠、活动、体重、检验和目标。
2. `compactContext` 对新增数据做字段白名单、长度限制和最近时间窗裁剪。
3. 服务端证据引擎计算个人目标对比、测量可比性、用药规律和同期生活方式线索。
4. 现有工具返回事实文本，同时附带稳定的个性化证据 ID、标签、事实和置信度。
5. Gemini 从证据目录中选择 1 至 3 条，只生成一句摘要和每条证据的一句解释。
6. 服务端按证据 ID 回填不可被模型修改的事实，并拒绝未知 ID、过长输出或缺少个性化证据的普通回答。
7. 前端在直接结论后展示“结合你的情况”模块，再展示少量解释和行动建议。

## 个性化证据

- `target-7d-average`：近 7 天平均值与医生家庭血压目标对比。
- `measurement-standardization`：有效测量比例、固定侧别、坐位、静坐时间和重复测量情况。
- `medication-adherence`：计划服药次数、按时、延迟和漏服情况。
- `lifestyle-overlap`：偏高日期与高钠、睡眠不足、活动不足或压力的同期重合，只表达关联。
- `weight-trend`：近期体重变化。
- `clinical-context`：已确认诊断、医生目标和与当前问题直接相关的检查背景。

工具只返回当前问题真正需要的证据。血压趋势优先目标、测量质量、用药和同期线索；饮食或睡眠问题优先对应生活方式证据；用药问题优先用药规律和安全边界。

## 回答结构

新增结构：

```json
{
  "title": "不超过18个汉字",
  "directAnswer": "2到3个短句",
  "personalization": {
    "summary": "一句话说明为什么结论适合当前用户",
    "evidence": [
      { "evidenceId": "稳定证据ID", "interpretation": "一句精炼解释" }
    ]
  },
  "keyPoints": [],
  "actions": [],
  "caution": "",
  "followUps": [],
  "dataBasis": "",
  "confidence": "high|medium|low"
}
```

约束：

- `directAnswer` 最多 220 字，目标为约 80 至 140 字。
- 个性化证据 1 至 3 条；紧急回答可以为空。
- `keyPoints`、`actions` 和 `followUps` 各最多 2 条。
- 事实由服务端回填，模型不能改写数值。
- 行动建议必须能对应本次证据，不输出泛化口号。

## 前端表现

- 新模块标题固定为“结合你的情况”。
- 顶部只显示 AI 的一句个性化摘要。
- 每条证据显示固定标签、确定性事实和 AI 的一句解释，并显示高/中置信度。
- 视觉上比普通解释卡更聚合，但不增加复杂图表或大段文案。
- 流式阶段仍先呈现直接结论，结论完成后一次性展开证据模块。

## 安全与校验

- 普通回答在存在证据目录时必须引用至少一条真实证据。
- 未知证据 ID、超过数量限制、核心字段缺失或输出过长触发 AI 修正。
- 紧急分诊不强制展示个性化模块，优先急救建议。
- 同期生活方式只使用“同时出现、值得继续观察”等措辞，禁止写成确定病因。
- 用药信息只能用于描述规律和准备就医信息，禁止建议自行加减停换药。

## 验证

- 测试新增数据能从样例进入 `brief` 和服务端受控上下文。
- 测试证据引擎输出固定事实、有效 ID和置信度。
- 测试模型只能引用证据目录，未知 ID 被剔除或校验失败。
- 测试普通回答必须含个性化证据，紧急回答允许省略。
- 测试前端存在“结合你的情况”模块并安全转义所有内容。
- 运行现有 Gemini 测试和样例统计不变量测试，确保没有回归。
